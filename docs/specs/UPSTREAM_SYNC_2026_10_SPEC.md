## User Stories

1. 作为搜索用户，我希望使用新增及更新来源，获得正确的真实分享链接、作品标题、提取码与元数据，而不是只有旧 19 个来源可用。
2. 作为 Panlian/Woniu 用户，我希望在 CLI 完成站点要求的人工登录，验证码或绑定邮箱确认未完成时不会被误报登录成功。
3. 作为 QQPD/Gying/Weibo 用户，我希望协议变更、旧索引和慢任务不会让已取得的结果整批丢失，错误与合法空结果可区分。
4. 作为 TG 用户，我希望同级按钮、正文和多链接消息均正确提取，日期行不被当作品名、别人的提取码不会串给当前链接。
5. 作为链接检测用户，我希望过期或禁止访问的 115 分享不再误报有效，读取和解压超限以不确定/错误报告而非错误判无效。
6. 作为现有用户，我希望升级保留显式来源选择、频道和账号，保持最终 table/JSON、检测及退出码契约，且不泄漏敏感数据。

## Implementation Decisions

### 1. 范围及旧规格优先级

- 本文替代 v1 的“仅 19 个 Provider、不得扩大范围”限制。其余 CLI 架构和安全约定保持，频道规格的后续输出/时限契约继续有效，本文明确变更的内容除外。
- 全部适用的局部净变化都迁移，包括仅代理、响应读取、重试或正则复用的来源；不能因 Rust 未实现而排除。基准前已有且没有适用局部净变化的历史来源不全面补齐。
- **不是上游这次新增 87 个来源**：上游新来源仅 10 个；87 是本次 Rust 新接入总数，包含本轮修改过的历史来源。完成后范围为 106 个 CLI 来源（19+87）。
- `xiaokupan` 仅 Go JSON 封装替换，`xuexizhinan` 仅格式化，不因此接入新来源。`dygang/haitunsou/rrbt/ting77` 无局部净差异，只继承框架变化，不额外接入。
- 上游停止注册但仍有适用局部变化的 `erxiao/jupansou/qupanshe` 保留为显式可选来源；源码存在、注册、默认启用、实际可用是四个不同概念。
- 不复制上游已识别缺陷，也不把文档宣称当代码事实；每个差异的确定处置见附录，无待核查文件。

### 3. 其余来源逐项更新

完整名单和每项净变化列于附录的三个 Provider 表，不另设“实施时核查”步骤。重点业务更新如下：

- **Panlian现代搜索**：`/api/videos`→`/api/videos/{id}`→POST link-ticket→GET link-open；最多10影片/并发4，每片最多解锁3条，优先不同盘型保护配额；type/type_name独立解析；保留真正旧部署接口回退，但可识别现代认证/业务失败不伪装成旧接口。配额POST不做盲重试。GET最多3次、200/400ms，认证/不可解析schema立即中止；20s每次，普通16MiB、ticket1MiB。
- **Panlian人工登录**：captcha获取图片与ID→用户名密码+图形码→必要时输入账号绑定邮箱核对；不是邮件OTP。HTTP200/400均解析业务状态，确认前不active；成功保存Cookie。过期清Cookie并提示人工重新登录，不再凭保存密码自动续期。图片私有临时文件/终端展示、可取消；非TTY需要明确交互入口，不能记录captcha/confirm ID或邮箱秘密。
- **QQPD官方解析**：替换HTML guild ID提取为gotrpc官方查询，校验p_skey/bkn与retcode/error.code；AppId及payload见附录。数字ID必须无前导零且在u64正数范围；15s/4MiB，EdgeOne挑战明确错误；data缺失失败、union_result null合法空。旧索引自动修复并持久化，失败不能把短号缓存成ID；inflight解析不能复活已删除频道。profile进入修复不再要求所有旧映射事先有效。
- **QQPD无效频道**：不照搬上游任意错误跨账号累计删除。仅类型化明确不存在code10003才累计；每profile连续两次、成功复位，隔离该profile目标并提示；传输/权限/未知码不得删除。连续计数存入profile，隔离可由配置操作恢复。
- **Gying**：PoW默认不加人工3s等待；会话10min运行期预热状态不能跨进程盲信；title/d/i必需数组按索引对齐，缺type不能默认mv请求错误详情；至少一账号合法空仍成功，全部账号失败才失败；403后保留已有成果，仅无成果且剩余足够、已保存凭据时命令内重登一次，无后台重登。
- **Weibo**：按用户任务增量收集，截止前保留快用户结果；搜索HTTP30→15s，评论仍30s、外链15s。搜索/评论/外链及QR状态/info/图片全部有限读；不把搜索超时误套到全部请求。
- **Libvio**：基准源码已为libvio.host，不是本轮源码换域名。新增CDN挑战403判别、SHA256(SIG+nonce) PoW，nonce上限2^22，Cookie握手与单飞，verified客户端复用25min；地域403不解题重试。CPU求解可取消，Cookie失效重解；搜索/详情/播放全链路生效。
- **Leso**：POST搜索→显式一跳Location GET→详情；搜索6MiB、详情8MiB、20s、30项/并发6；缺Location/最终非200报错，全详情失败与合法空搜索分开；补no-follow客户端分支测试。
- **Yingso**：新`/test1`+672134612、旧`/test`+12345678成对回退；getKey670I23762183→getKey；UTF16 code-unit XOR，0≤start<end≤24；总25s/1MiB/并发8。坏配置/业务失败也回退，不只404。
- **Yunso**：明文、Base64、新旧XOR三路在分类/密码/去重前统一去空query `?`；保留真实query/fragment/编码问号。与xys/yunsou不是同一来源。
- **Zhizhen**：唯一入口`http://www.mihdr.top`，不强改HTTPS或保留失效旧域名轮询；搜索/详情各25s，明确明文HTTP。
- **Nsgame**：难度合法0..256，负数/>256拒绝，nonce最多千万且受取消/CPU预算约束；读失败不可吞半截成功。
- **Pansearch**：RFC3339失败后尝试UTC `YYYY-MM-DD HH:mm:ss`，仍失败保留无时间并诊断。
- **Dyyj**：确有文本密码正则空白修复；Rust保留已正确实现并回归，不因Go旧HTML路径变化放弃当前JSON API。

所有仅安全/性能变化的来源也有明确接入要求和各自协议基线；具体次数、阶段和边界以附录逐项表为准，不虚构站点API变化。

### 4. 公共HTTP、安全与重试

- 统一所有搜索、详情、验证、登录、QR、短链和临时no-follow客户端；保留CLI/PANSOU_*现有优先级，补兼容环境大小写、ALL_PROXY和显式代理NO_PROXY。SOCKS5/SOCKS5H保持Rust库正确DNS语义，不照搬Go归一注释。
- 默认池参考每host空闲110、保活600s，连接复用不破坏独立Cookie jar；Debug/错误链/无效代理地址同样脱敏，不能只脱敏Display。
- 原始响应默认16MiB；TG2MiB及逐来源更小上限优先。gzip/zlib解压绝对64MiB；已知压缩长度时`min(64MiB,max(400KiB,100×压缩长度))`。明确控制自动解压层，分别约束输入/输出；无Content-Length仍流式计数，恰等上限通过、+1失败，不把超限当EOF。
- 部分Provider净变化只增加64MiB绝对解压上限，没有直接使用压缩比工具；本项目集中按上述安全策略落地，不混淆上游调用事实。
- TLS继续默认校验，不新增不安全证书绕过开关；上游从硬编码不安全改为显式风险配置的安全目标已由现有Rust强约束覆盖。
- 统一可取消重试工具，总尝试含首次、末次不等待、失败体及时释放、POST body可重放、保留真实状态码/错误链。支持中止、固定/线性/指数等待，具体采用哪种以逐来源表为准，不强推jitter。

### 5. TG、核心解析与9个checker

- 按消息wrap而不只是message内部提取同级inline keyboard；保持本消息边界，正文/按钮/裸链接统一归集、去重与补码。
- DOM投影仅br换行，内联标签不凭空换行；标题跳日期/元数据/纯标签行，保留名称前缀及简介裁剪规则。缺可选时间不丢有效链接，整页结构异常给明确诊断，合法无消息/无支持链接仍为空结果。
- 密码顺序为显式URL码→链接局部码→无歧义共享码。局部窗口最多60 bytes、UTF8安全、下一链接前截断；短按钮标签可取码。不复制上游near覆盖URL码、错误空白正则和把首码强填其他链接的缺陷。
- 百度无码链接保留、非空码不被空码清除、UC share ID中的`123`不截断；TG正文关键词命中保留已有等价行为并补准确回归。没有新增TG分页或结果评分权重变化。
- 115先取顶层share_state，0时回落嵌套；forbid_reason非空先判锁定/失效。有列表/数量/snap/title不能盖过禁用状态；只有无禁用原因、状态0或1且活跃/有内容才有效。
- 9 checker共享读取/解压边界，超限按Uncertain/错误而非Bad。Mobile仅Go JSON替换，无加密协议变化；检测缓存读写告警已有实现，补损坏条目回归，不引入Bolt。
- Woniu返回的微云、蓝奏盘型扩展公共`CloudType`为`Weiyun`、`Lanzou`，CLI过滤名及JSON序列化值固定为`weiyun`、`lanzou`，不降级为Others。同步域名边界识别、FromStr/Display、`--cloud`解析/帮助、结果合并和序列化往返；合法微云/蓝奏域名按hostname及合法子域匹配，URL路径/query含域名文字不能误判。
- 不新增checker或默认有效豁免；Weiyun/Lanzou检测明确返回Unsupported，默认搜索仍按既有检测规则过滤，`--no-check`可输出并按新类型筛选。Magnet/ED2K沿现有特例，文档区分可识别与可检测。

### 6. CLI截止、部分成果与资源约束

- 保留source共享并发默认8、单源30s、搜索总600s、排队不占单源执行时间等契约；不照搬Go10s默认、4s异步窗或3.2s发布预算。
- source并发与内部请求扇出分别有界；共享HTTP出口默认硬上限128，等待槽可取消，覆盖TG、Provider内部详情、认证/转存等真实请求；不把Go只包前台Search的信号量误称HTTP全覆盖。
- 来源开始时确定唯一deadline，预热/重登/重试/轮询/解题/详情共享，不能每阶段重置延长。没有脱离命令生命周期的任务或后台补搜。
- 扩展内部结果契约：Provider可将已有效解析的增量交给编排持有的来源收集器；正常返回与增量统一去重。外层timeout/drop时仍能取截止前快照，取消后禁止继续写入；仅最终Vec返回不足以保证保留部分成果。
- completed/failed/cancelled/not-started终态互斥且总和等于选定source数；完整空成功计completed，部分链接不算完整成功。所有未完整成功来源令partial=true，失败与产出诊断写stderr/现有结构，不污染最终JSON。

| 情况 | 终态与成果 | 退出码 |
| --- | --- | --- |
| 正常结束，有至少一个完整成功来源 | 其余失败仍诊断，保留符合检测规则的完整/部分成果 | 0 |
| 正常结束，无完整成功来源，即使有部分链接 | 来源错误或自身超时计failed，保留已有成果 | 3 |
| 搜索总截止 | 完成终态不变，运行中cancelled，排队not-started | 124 |
| Ctrl-C | 完成终态不变，运行中cancelled，排队not-started，并取消检测 | 130 |

总截止/中断优先于普通结束；认证、参数及初始化专用状态沿用现有约定。
