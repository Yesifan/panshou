## Maintenance

- 每个 spec（包括子目录内的 spec）都应在索引添加相对链接和一句话用途。
- 实施 spec 时同步维护代码和文档，使约定与行为一致。
- 新增、重命名、移动、删除 spec，或其用途、状态、执行日期变化时更新索引；元数据是状态和执行日期的事实来源。
- 已完成规格保持原文不变；后续变更新建规格，链接原规格并说明替代、调整或扩展的约定，同时在索引记录关系。
- 新规格使用 `status`（`not-started` / `in-progress` / `completed`）和 `execution_time`（创建日期；完成后为创建/完成日期）元数据；可补充实现 commit、版本和相关文档。
- 历史规格没有这些元数据，保留其原文并如实标注；不从未勾选 checklist 推断未实现，也不把历史测试说明视为当前验收结果。
- 同步附录是父规格的组成部分，不是独立 spec；当前同步范围由已完成的两端点净 diff 核查确定，不维护逐 commit 清单或待填核查台账。核查完成、代码实现、测试通过和线上可用必须分别表述。
