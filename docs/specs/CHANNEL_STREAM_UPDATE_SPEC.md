# PanSou 频道管理、流式搜索与自更新规格

状态：已实现。本机格式检查、Clippy、185 项测试及 Release 构建通过；跨平台运行验收由 CI 完成。

本文定义目标、用户可见功能、范围边界及验收标准，不规定内部实现方式。
本文与既有 Rust CLI v1 规格在频道配置、搜索输出和超时行为上冲突时，以本文为准。

## 1. 目标

- 用户可以持久管理 Telegram 频道，决定哪些频道参与日常搜索。
- 用户可以导入仓库维护的候选频道，也可以使用自己的本地或远程清单。
- 搜索有结果就输出，避免等待全部来源结束后才能看到结果。
- 保持当前默认 8 并发，明确单来源超时和整次搜索阶段的等待上限。
- 修复 Telegram 按钮链接及正文关键词命中被遗漏的问题。
- 用户可以通过 CLI 更新程序，获得必要的自动迁移或手动处理提示。

## 2. 功能

### 2.1 频道管理

提供以下命令：

```bash
pansou channel list
pansou channel add NAME_OR_URL... [--disabled]
pansou channel remove NAME...
pansou channel enable NAME...
pansou channel disable NAME...
pansou channel catalog
pansou channel import --builtin
pansou channel import FILE_OR_URL
pansou channel path
```

例如，以下命令添加 `foo` 和 `bar` 两个频道：

```bash
pansou channel add @foo https://t.me/bar
```

行为要求：

- 接受公开频道名称、`@名称`、`https://t.me/名称` 和 `https://t.me/s/名称`。
- 同一频道的不同输入形式及大小写不产生重复记录。
- 拒绝空名称、非法名称、私有邀请链接和非 Telegram 频道地址。
- 添加频道默认启用，`--disabled` 表示仅保存而不启用。
- 添加已存在的频道保留其启用状态；重复启用或禁用不改变结果。
- 启用或禁用不存在的频道报错；删除不存在的频道报告未找到。
- 批量操作完成校验后统一生效，不因参数错误或超限留下部分修改。
- `list` 显示频道名称、启用状态、启用数量、上限和保存总数。
- `path` 显示用户频道配置文件的绝对路径。
- 保存频道总数不设业务上限；同时启用最多 128 个频道，约束名称为
  `MAX_ENABLED_CHANNELS`。
- 超限时明确报错，不静默截断，也不自动禁用其他频道。
- 用户手工配置超限后，仍能通过查看、禁用、删除等命令修复。

### 2.2 独立频道配置

频道持久配置统一使用应用配置目录中的 `channels.toml`。

- 废弃 `config.toml` 中的 `search.channels`，不再用于选择搜索频道。
- 不自动复制或迁移旧频道列表。
- 检测到旧字段时提示使用频道命令重新添加或导入，并提示可以删除旧字段。
- 旧字段不能使帮助、更新和频道管理命令无法启动。
- `config show` 不把旧字段显示为有效频道配置。
- 新频道文件不存在时保留当前初始默认频道 `tgsearchers3`；显式保存的空清单或
  全部禁用的清单不能恢复默认频道。
- 普通搜索和软件升级不自动导入候选清单，不恢复用户删除的频道。
- 保存失败不损坏原有清单；同时执行管理命令不能丢失已成功保存的修改。

本次搜索的频道选择优先级从高到低为：

1. 命令行 `--channel`。
2. 环境变量 `PANSOU_CHANNELS`。
3. 兼容环境变量 `CHANNELS`。
4. 独立频道配置中的已启用频道。

各层整体覆盖，不追加。环境变量及命令行参数仅影响本次运行，不写回配置。
显式空环境变量可以清空频道选择；显式指定允许临时搜索未保存或已禁用的频道。
最终去重后的本次搜索频道数也不得超过 128。

`--source provider` 不搜索 TG；`--source tg` 不搜索 provider。
没有任何搜索来源时应明确报错。

### 2.3 候选清单与导入

仓库维护候选频道清单，并随程序发布。`channel catalog` 可离线查看当前版本内置清单。
清单注明来源；列入清单不代表已验证频道当前可用。

导入支持：

```bash
pansou channel import --builtin
pansou channel import ./channels.txt
pansou channel import https://example.com/channels.txt
```

- 三种来源使用相同的 UTF-8 文本格式：每行一个频道名称或地址，允许空行及以 `#`
  开头的整行注释。
- 内置导入与文件或 URL 参数互斥。
- 新增频道默认禁用；已有频道保留原状态。
- 重复导入不产生重复记录。
- 非法条目报告行号，整次导入不生效。
- 远程导入支持 HTTP(S)，沿用网络和代理配置，并有请求超时及大小限制。
- 下载失败、非成功响应或解析失败不修改现有频道。
- 完成后显示新增数、已有数，并说明新增频道处于禁用状态。

### 2.4 搜索并发与超时

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--jobs` | 8 | TG 与 provider 共享的 source 并发数 |
| `--timeout` | 30 秒 | 每个来源开始执行后的超时，不含排队 |
| `--all-timeout` | 600 秒 | 搜索阶段总时限，包含排队与搜索执行 |

一个 TG 频道或一个 provider 各算一个 source。所有来源共享当前并发策略，不增加 TG
独立并发限制。上述参数必须大于零。

总时限支持 `search.all_timeout_secs` 配置及 `PANSOU_ALL_TIMEOUT_SECS` 环境变量，
优先级为命令行、环境变量、配置文件、默认值。

- 全部来源提前结束时立即完成搜索。
- 单来源失败或超时不阻止其他来源继续运行。
- 到达总时限后停止剩余搜索，保留已接收结果，明确报告搜索不完整。
- 区分成功、失败、运行中被取消和尚未开始的来源。
- 总时限不包含初始化和链接校验，不能描述成整个命令的绝对耗时上限。
- Ctrl-C 停止搜索与校验，已输出内容保留。

### 2.5 默认流式输出

搜索默认以来源完成为粒度输出：一个频道或 provider 返回后，完成必要过滤和去重，
立即展示结果，不等待其他来源结束。

```bash
pansou search "仙逆"
pansou search "仙逆" --format jsonl
```

- 搜索只支持 `table` 和 `jsonl`，默认 `table`。
- 移除搜索的 `json` 格式；使用该格式时提示改用 `jsonl`。
- 不需要 `--stream`，不提供等待所有来源后一次性输出的搜索模式。
- 表格持续追加，不清屏、不重排旧记录。
- JSONL 每行一个完整事件，及时输出，管道调用方不必等待程序退出。
- 搜索结果及结构化事件输出到 stdout；进度和普通诊断输出到 stderr。
- `--quiet` 隐藏进度及普通提示，不隐藏结果和结构化摘要。

JSONL 提供以下用户可见事件：

| 事件 | 含义 |
| --- | --- |
| `result` | 首次发现的链接 |
| `result_update` | 同一链接更新后的完整记录 |
| `source_error` | 来源错误 |
| `summary` | 最终统计和结束原因 |

首次记录和后续更新使用相同的稳定链接标识。

### 2.6 过滤、去重与结果更新

- 保留 `--include`、`--exclude`、`--cloud` 及各 provider 自身的关键词语义。
- 在整次搜索范围内按规范化 URL 去重，首次发现立即输出。
- 后续来源补充提取码或更新元数据时，产生更新记录；完全相同的记录不重复输出。
- 表格以 `UPDATE` 标明更新，JSONL 使用 `result_update`。
- 最终链接数统计唯一链接，不把更新事件重复计数。
- 保留完成批次内部的排序，跨来源按完成顺序输出，不承诺最终全局排名。

### 2.7 Telegram 搜索修复

资源提取覆盖正文文本、正文链接及 inline keyboard 按钮链接。

- 能识别仅放在按钮中的资源链接。
- 能从正文和按钮文字提取提取码。
- 正文和按钮中的同一链接合并，补齐缺失信息。
- 有按钮资源链接但缺少正文的消息仍可保留，并使用可用文字生成展示标题。
- 不含受支持资源链接的消息仍丢弃。

TG 本地关键词过滤规则：

1. 正文包含完整查询词时，保留该消息及其已识别链接。
2. 正文未命中时，检查链接作品标题，缺失时检查消息标题。
3. 删除不匹配的链接，没有剩余链接时丢弃消息。

查询去除首尾空白，匹配不区分大小写。保留每频道一次公开搜索页请求的行为。

### 2.8 链接校验

- `--check` 在链接完成校验后输出。
- `--valid-only` 仅输出已确认有效的链接。
- 校验不阻塞其他搜索来源结果的接收。
- 同一链接避免不必要的重复校验；影响校验的提取码变化等更新应正确处理。
- 搜索总时限到达后，已接收结果的校验可以继续；用户中断同时取消校验。
- 因此开启校验后，命令耗时可能超过 `--all-timeout`，必须明确提示。

### 2.9 摘要与退出状态

最终摘要应报告唯一链接数、选中来源数、成功数、失败数、取消数、未开始数、是否
不完整、结束原因、搜索阶段耗时及包含校验的处理耗时。

选定来源中存在未成功完成的来源时，标记 `partial=true`。全部成功但结果为空属于
完整的空结果，不算失败。

| 情况 | 退出码 |
| --- | --- |
| 正常结束且至少一个来源成功 | 0 |
| 参数或配置错误 | 2 |
| 所有来源失败 | 3 |
| 搜索总时限到达，包括已有部分结果 | 124 |
| 用户中断 | 130 |

原有其他命令的专用退出状态不受本表影响。

### 2.10 Help 与等待时间

`pansou help` 和 `pansou search --help` 说明：

> 搜索来源中的资源命名可能不规范。建议使用简短的核心关键词，关键词过长可能降低搜索效果。

`pansou help` 根据当前配置显示：

- 实际会参与默认搜索的 provider 数量。
- 已启用频道数和 128 上限。
- 并发数、单来源超时、搜索阶段总时限。
- 搜索阶段预计最长等待时间。
- 默认逐来源输出，以及初始化和链接校验可能额外耗时的说明。

估算口径为：

```text
min(向上取整((provider 数 + channel 数) / jobs) × timeout, all-timeout)
```

例如，15 个 provider、128 个频道、8 并发、单来源 30 秒、总时限 600 秒时，估算为
540 秒，约 9 分钟。该数值是调度耗时估算，不是精确墙钟保证。

- provider 是否就绪依据本地配置和登录状态判断；help 不发网络请求。
- 搜索开始时按本次参数重新显示摘要，`--quiet` 可隐藏。
- 配置损坏时静态帮助仍可查看，动态摘要说明无法计算。
- 查看帮助不修改配置，不触发迁移。

### 2.11 自更新

```bash
pansou update
pansou update --check
pansou update --version v0.2.0
```

- 默认检查 `Yesifan/panshou` GitHub Releases 的最新稳定版并安装。
- `--check` 只检查和显示信息，不安装；可与 `--version` 组合。
- 使用语义化版本比较；默认不重复安装、不自动降级。
- 显式指定旧版本时必须检查本地数据兼容性，不能破坏较新格式的数据。
- 显式执行更新即授权该次更新，不增加交互确认。
- 显示当前版本、目标版本及相关升级说明。
- 支持发布所覆盖的平台和架构，沿用代理配置。
- 更新当前使用的安装位置，不另装一份导致实际运行版本没有改变。
- 安装前验证下载完整性及目标程序版本。
- 下载、校验或兼容性检查失败不影响当前安装。
- 安装目录不可写时给出路径和处理办法，不自动提权。
- 明确由包管理器管理的安装，提示使用对应包管理器更新。
- 更新成功后报告实际安装版本；各阶段失败给出准确状态，不误报成功。
- 配置不兼容时，更新和基础帮助入口仍然可用。

### 2.12 自动迁移与手动升级提示

程序升级可以对含义明确的数据格式变化自动迁移，对需要用户选择的变化输出手动
处理说明。程序版本用于识别升级变化，数据格式版本用于判断必要迁移。

自动迁移应满足：

- 修改前保留可恢复的原数据。
- 重复执行不会重复转换已完成的数据。
- 跨多个程序版本升级时不会遗漏必要迁移。
- 失败不损坏原数据，并报告受影响功能和处理方法。
- 用户通过安装脚本或手动替换程序升级后，仍能获得必要迁移检查。
- 降级时不能改坏旧程序不理解的新数据。

手动事项根据实际情况显示，不向未受影响用户输出无关警告：

| 本次变化 | 提示 |
| --- | --- |
| 废弃 `search.channels` | 使用频道命令重新添加或导入，不自动复制旧列表 |
| 搜索移除 JSON | 改用 JSONL |
| 默认流式搜索 | 输出按来源完成顺序，JSONL 为事件流 |

- 未解决事项在相关命令中继续简短提示，解决后不重复提示。
- 跨版本升级汇总仍然相关的事项。
- 不相关事项不阻止命令；必须处理的问题给出具体操作。
- 区分程序安装成功与数据迁移成功。迁移失败时明确说明，不宣称升级全部完成。
- 数据格式已变化时，不能仅恢复旧程序就宣称完整回滚。

## 3. 不做的事

- 不增加频道重命名、别名、分类、优先级或自动健康评分。
- 不自动迁移旧 `config.toml` 频道列表，不静默删除旧配置字段。
- 不因升级自动导入、启用候选频道或恢复已删除频道。
- 不允许超过 128 个频道参与单次搜索，也不限制保存的禁用频道总数。
- 不改变默认共享 8 并发为独立 TG 并发池。
- 不增加 Telegram 翻页、自动重试、搜索缓存或未知中转网站解析。
- 不增加中文自动分词、模糊匹配、同义词扩展或多个查询自动重试。
- 不要求 provider 内部逐页流式输出。
- 不提供搜索 JSON 格式和等待全部来源后一次性输出的模式。
- 不承诺流式结果全局排序，不回撤或重排已经输出的记录。
- 不修改独立 `check` 命令的输出格式。
- 不在普通搜索时自动检查更新，不自动安装预发布版本或自动提权。
- 不执行发布说明或远程清单中的脚本，不代替用户重新登录 provider。
- 不在本文规定模块划分、文件写入算法、依赖库或事件字段的内部实现。

## 4. 验收标准

### 4.1 频道与导入

- [ ] 能添加、删除、启用、禁用多个频道，重复操作符合上述语义。
- [ ] 名称、`@名称`、公开 URL 和大小写变体只产生一个频道记录。
- [ ] 启用第 129 个频道失败，原状态不变；禁用频道仍可继续保存。
- [ ] 参数、环境变量及手工文件修改不能绕过单次 128 频道上限。
- [ ] 三种导入来源行为一致，新增项禁用，已有状态不变。
- [ ] 非法行报告位置；下载、解析或保存失败不留下部分修改。
- [ ] 同时执行修改不会丢失已成功保存的频道。
- [ ] 旧 `search.channels` 不影响搜索、不自动迁移，并产生针对性提示。
- [ ] 显式空清单和全部禁用状态不恢复默认频道。
- [ ] 临时覆盖不写回文件；普通搜索和升级不改变用户频道选择。

### 4.2 搜索与输出

- [ ] 慢来源未结束时，stdout 已能读到快来源的结果。
- [ ] 默认最多 8 个 source 同时执行，TG 和 provider 共享限制。
- [ ] 排队时间不消耗单来源超时，但计入总时限。
- [ ] 总时限到达后剩余搜索停止，已有结果保留，统计和退出码正确。
- [ ] 成功空结果、单来源失败、全部失败和用户中断可明确区分。
- [ ] 跨来源重复链接不会重复计数，密码等元数据更新可被用户或调用方识别。
- [ ] Table 可以持续追加；JSONL 每行合法、及时可读，不混入普通日志。
- [ ] `search --format json` 给出改用 JSONL 的提示；独立 check 格式不变。
- [ ] 校验不阻塞其他搜索结果接收，`--valid-only` 不输出未经确认的链接。

### 4.3 Telegram 与帮助

- [ ] 仅存在于按钮中的资源链接能够返回。
- [ ] 按钮内提取码可被识别，正文与按钮重复链接正确合并。
- [ ] 缺少正文但有按钮资源的消息不会被直接丢弃。
- [ ] 标题未命中、正文命中的消息能够保留；无资源链接的消息仍丢弃。
- [ ] help 包含简短关键词建议及搜索阶段时限说明。
- [ ] help 根据实际本地配置计算来源数和等待估算，不联网、不修改配置。
- [ ] 配置异常时仍能查看基础帮助。

### 4.4 更新与升级

- [ ] 能检查最新稳定版、仅检查以及选择指定版本。
- [ ] 正确选择受支持平台资产，成功后实际运行版本与目标一致。
- [ ] 下载失败、校验不通过、缺少资产或权限不足不破坏现有安装。
- [ ] 支持的各平台更新行为有验证，包括 Windows 当前程序的替换。
